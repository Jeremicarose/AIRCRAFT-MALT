# Follow-up and Opportunity Pipeline

## Seven-day rule

Every completed session ends with exactly one next action and a deadline within
seven days. `No further action` is a valid result. Do not invent a meeting or
integration task to make a participant look qualified.

Examples include another usability test, SDK evaluation, API review, network
integration test, larger receiver test, partnership discussion, introduction,
or a written decision not to continue.

## Qualification path

```text
Participant -> Problem validated -> Product fit -> Continued interest
            -> Technical discussion -> Integration discussion
            -> Pilot expansion -> Commercial or partnership opportunity
```

A potential client or partner must have all five:

1. A real problem described from experience.
2. Clear relevance to Registry identity or MLAT receiver provenance.
3. Authority or influence over the workflow.
4. Direct interest in continuing.
5. One concrete, dated next action.

## Classifications

- `Confirmed opportunity`: all five qualification conditions are supported by
  direct evidence and the next action is accepted by both sides.
- `Promising lead`: problem and relevance are supported, but authority,
  commitment, or the next action is not complete.
- `Speculative opportunity`: public research suggests possible fit, but no
  direct product or interest evidence exists.

Never combine these categories in totals.
